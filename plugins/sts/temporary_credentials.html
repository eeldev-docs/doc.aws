STS

Temporary Credentials

Assume a role​

Create an IAM role in the AWS console with the permissions you need, and a trust policy that allows your IAM user to assume it. Then call Assume Role with:

FieldValue
Role ArnThe ARN of the role, for example arn:aws:iam::123456789012:role/GameUploader.
Role Session NameA name for the session, for example the player id. It shows up in CloudTrail.
Duration SecondsHow long the credentials are valid, from 900 (15 minutes) up to the role's maximum session duration. 0 means 1 hour.
PolicyOptional JSON policy that limits the credentials further.

Use the credentials​

The result has Credentials with Access Key Id, Secret Access Key, Session Token and Expiration.

Use them when you create the client object of another plugin, for example Create Aws S3 Object:

STS resultCredentials input
Access Key IdAccess Key Id
Secret Access KeySecret Key
Session TokenSession Token
warning

All three values are needed. Without the Session Token, AWS rejects the credentials with INVALID_CLIENT_TOKEN_ID.

The credentials stop working at Expiration. Get new ones before that, and create the client object again with them.

Other ways to get credentials​

NodeUsed for
Get Session TokenTemporary credentials for the IAM user itself. Add Serial Number and Token Code to use MFA.
Assume Role With Web IdentityCredentials for a player signed in with an OpenID Connect provider, without an IAM user.
Get Federation TokenCredentials for a federated user with a policy you choose.

For players signing in with your own accounts, Cognito identity pools are often easier.
